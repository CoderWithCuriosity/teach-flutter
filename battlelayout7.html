⚡ The one new idea in this battle

Extracting a widget into its own StatelessWidget class. Right now your expense row is a big chunk of code that lives inside the itemBuilder. Every battle before this, you wrote widgets inline. That's fine for one-offs. But when you need to reuse a widget — or when the file gets too long — you pull it out into its own class.

Think of it like this: instead of writing "the row with icon, text, and amount" as a wall of code inside the builder, you write a class called ExpenseRow with a build() method. Then the builder just says return ExpenseRow(item: expenses[i]); — clean and short.

That's the entire concept. Same visuals. Same widgets. Just better organized.

📎 Shape of the code (skeleton — you fill in the details)

// 1. data class (same idea as Battle 6) class Expense { final String title; final String subtitle; final String amount; final bool isIncome; Expense({required this.title, required this.subtitle, required this.amount, this.isIncome = false}); } // 2. your own widget class — the new idea class ExpenseRow extends StatelessWidget { final Expense item; const ExpenseRow({super.key, required this.item}); @override Widget build(BuildContext context) { // return the Row you already know — same as Battle 6 } } // 3. inside the list builder ListView.builder( itemCount: expenses.length, itemBuilder: (context, i) => ExpenseRow(item: expenses[i]), )
